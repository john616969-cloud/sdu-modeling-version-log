# 50 MB 分片上传与自动刷新实施计划

## 目标

- 单文件允许上传至 50 MiB，前后端保持同一限制。
- 10 MiB 以内继续保存为普通 Git 文件；更大的文件按 5 MiB 分片保存，并通过清单透明下载和恢复。
- 已登录成员的页面每 30 秒检查一次新版本；重新回到页面或恢复联网时也立即检查。
- 发现其他页面提交的新上传或恢复记录后，刷新最新版本与日志，并在现有页内提示区提醒所有成员。

## 实施步骤

1. 新增统一上传常量、分片清单格式、校验与通知摘要函数，并补充边界测试。
2. 改造 GitHub 提交流程：直接文件与分片文件共用一次原子提交；恢复分片版本时复用既有分片。
3. 改造下载流程：识别清单、按顺序读取和校验分片、合并为原文件。
4. 将上传接口和页面限制改为 50 MB，并让上传/恢复接口返回的事件立即成为当前页面的已读事件。
5. 增加后台轮询、页面重新可见和恢复联网时的刷新；401 时退出到登录页，普通网络故障静默重试。
6. 更新说明文档，运行测试、类型检查、规范构建与本地预览。
7. 提交并同步源代码，保存和发布新的 Sites 版本，最后进行只读线上检查。

## 验证重点

- 10 MiB、10 MiB + 1 字节、50 MiB、50 MiB + 1 字节边界。
- 分片清单路径、大小总和和 SHA-256 校验。
- 普通旧文件仍可下载；分片文件可还原为原始文件名和字节。
- 初次加载不提示；无变化不提示；一条及多条新记录提示正确。
- 当前页面自己的上传或恢复不产生重复通知。
