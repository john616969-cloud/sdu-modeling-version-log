# 私有访问审计日志设计

## 目标

在现有数模版本站中记录成员成功登录和成功下载文件的行为，并只允许张怡慧查看这些访问记录。系统继续使用现有私有 GitHub 数据仓库存储业务数据，不引入数据库或新的第三方服务。

## 身份与权限

- 登录页先要求选择成员姓名，再输入密码。
- 张怡慧使用独立管理员密码；陈鑫和谷雨蔓继续共用原团队密码。
- 服务端只保存 PBKDF2-SHA256 加盐密码哈希，任何代码、Git 提交、接口响应和日志都不得包含明文密码。
- 登录成功后，七天会话载荷增加成员姓名和角色。张怡慧会话角色为 `admin`，另外两位成员为 `member`。
- 姓名和角色只能由服务端根据“所选姓名 + 对应密码”签发，客户端不能自行提升权限。
- 陈鑫和谷雨蔓因为共用密码，技术上可以互选姓名；界面将姓名作为操作确认，日志记录所选择的姓名。这是已确认接受的限制。
- 现有会话升级后，旧格式会话不具备成员身份，视为无效并要求重新登录一次。

## 审计事件

只记录完成的操作：

- `login`：密码验证成功且会话已签发。记录事件 ID、所选成员姓名和北京时间。
- `download`：目标文件读取成功。记录事件 ID、成员姓名、北京时间、文件名、仓库路径，以及能够从版本索引匹配到的版本号和分类。

密码错误、限流拒绝、文件不存在和下载失败不写入审计日志。日志不保存密码、密码哈希、Cookie、GitHub 令牌、IP 地址、地理位置或完整设备信息。

## 数据存储

- 审计数据写入现有私有 GitHub 数据仓库的 `audit/` 目录，不进入公开的网站源码仓库。
- `audit/index.json` 保存按时间倒序排列的最近 500 条记录，便于网页读取。
- 每个事件同时保存为 `audit/entries/<timestamp>-<event-id>.json`，形成可追溯的 Git 历史。
- 写入采用与版本上传相同的 Git Data API 原子提交方式，并在分支并发更新冲突时最多重试三次。
- 审计写入失败时采用“操作成功、审计尽力记录”的策略：登录或下载本身不因 GitHub 日志临时失败而被阻断，服务端输出不包含敏感细节。这样比赛期间 GitHub 短暂异常不会导致成员无法取文件。

## 服务端接口

- 登录接口接收 `member` 和 `password`，校验成员是否在配置名单中，并按成员角色验证对应密码哈希。
- 文件下载接口从经过签名的会话读取成员姓名；成功取得文件后写入下载事件。
- 新增管理员审计接口，返回最近的访问事件。它必须同时验证有效会话和 `admin` 角色。
- 普通成员访问管理员接口返回 `403`；未登录请求返回 `401`。
- 管理员接口和页面响应均设置 `Cache-Control: private, no-store`。

## 页面行为

- 登录卡片增加成员姓名选择框。
- 工作台仅在管理员会话中显示“访问日志”入口。
- 访问日志以表格显示时间、成员、操作，以及下载事件对应的文件和版本；默认最新事件在前。
- 普通成员页面不获取、不嵌入审计数据。即使手动输入管理员页面地址，也无法从接口读取记录。
- 页面继续保持简体中文和七天自动登录提示。

## 配置与迁移

- 新增管理员密码哈希配置，与原团队密码哈希分开保存为托管环境密钥。
- 原团队密码哈希继续用于陈鑫和谷雨蔓。
- 部署时只上传密码哈希，不上传用户提供的明文密码。
- 因会话结构改变，发布后所有设备需重新登录一次，此后仍保持七天。

## 错误处理

- 未知成员、密码格式无效和密码错误统一返回不泄露内部配置的中文错误。
- 审计读取失败时，管理员页面显示可重试提示，不展示 GitHub 令牌、仓库响应正文或堆栈。
- 并发审计提交冲突在服务端重试；最终失败只进入服务端错误输出，不影响已经完成的登录或文件下载。

## 测试与验收

- 三名成员只能用各自适用的密码规则登录，错误组合被拒绝。
- 签名会话正确包含成员和角色，篡改、过期及旧格式会话均被拒绝。
- 张怡慧登录后能读取审计接口；另外两名成员收到 `403`；匿名请求收到 `401`。
- 成功登录产生一条 `login` 事件；失败登录不产生事件。
- 成功下载产生一条带文件信息的 `download` 事件；失败下载不产生事件。
- 审计索引按时间倒序且最多保留 500 条。
- 普通成员界面不显示访问日志入口，也不预取审计数据。
- 所有审计响应禁止缓存，源码仓库与构建产物中不出现明文密码。
- 单元测试、代码检查和生产构建通过后重新部署；线上分别验证管理员和普通成员的权限边界。

## 已知限制

- 陈鑫和谷雨蔓共用同一密码，系统只能证明登录者知道该密码并选择了某个姓名，不能从密码本身证明两人中的真实操作者。
- GitHub 仓库写入存在网络延迟和服务限额，因此审计采用尽力记录而不是阻断核心操作。
- 具有私有数据仓库管理权限或托管环境管理权限的人仍能直接查看或修改底层数据；“只有张怡慧可见”指版本站的应用权限边界。
