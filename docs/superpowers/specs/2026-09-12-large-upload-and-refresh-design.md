# 50 MB 上传与新版本自动刷新设计

## 目标

将网页的单文件上传上限从 20 MB 调整为 50 MB，并降低大文件在 Cloudflare Worker 内存中编码时失败的风险。所有已打开网页的成员应在发现新的上传或恢复版本后收到页面内提示，最新版卡片和版本日志自动刷新。

## 上传限制

- 前端和服务端统一采用 50 MiB 上限，即 `50 * 1024 * 1024` 字节。
- 空文件继续拒绝，超过上限返回明确的中文提示和 HTTP `413`。
- 上传区域显示“最大 50 MB；代码请先打包为 ZIP”。
- 50 MB 是本网站的明确上限，不宣称无限制。GitHub 普通 Git 对象仍受 100 MiB 硬限制，Cloudflare 请求体和 Worker 内存也存在平台限制。

## 大文件分块存储

- 不超过 10 MiB 的文件沿用现有单一 Git blob 存储方式。
- 大于 10 MiB、且不超过 50 MiB 的文件在服务端按 5 MiB 分块。
- 每个分块独立创建 Git blob，降低 base64 编码和 JSON 请求的瞬时内存占用。
- 分块路径使用 `chunks/<event-id>/part-00001` 等不可冲突的名称。
- 版本原路径保存一个小型 JSON 清单，包含固定格式标识、原文件名、总大小、完整文件 SHA-256 及按顺序排列的分块路径和大小。
- 文件名、版本号、分类、成员、说明等现有版本日志字段保持不变；网页不向成员暴露内部清单和分块结构。
- 整次上传仍通过一次 Git tree 和一次 commit 原子落库；分支更新并发冲突继续最多重试三次。
- 并发重试可能产生未被最终 tree 引用的临时 blob，GitHub 会自行处理不可达对象，不向页面展示。

## 下载与恢复

- 下载服务首先读取版本原路径。普通文件沿用现有读取方式。
- 检测到受支持的分块清单时，按顺序读取所有分块并合并为原始字节，下载响应继续使用原文件名。
- 合并前校验清单格式、分块数量、路径前缀和声明总大小；异常清单拒绝下载。
- 合并后校验总大小。完整 SHA-256 保留在版本日志中；本次不重复计算下载摘要，避免不必要的内存副本。
- 恢复分块版本时复制清单 blob，并继续引用原分块；不会重复保存相同的大文件内容。
- 现有普通历史文件继续兼容，不执行数据迁移。

## 新版本检测

- 已登录工作台成功加载后保存当前最新版本事件 ID，首次加载不显示历史提示。
- 页面打开期间每 30 秒请求一次版本摘要。
- 页面从后台回到前台或网络恢复时立即检查一次。
- 如果摘要首条事件 ID 与上次已见事件不同，则用新摘要替换当前最新版卡片和完整版本日志。
- 提示显示最新事件的成员、类别和版本；若一次检查发现多条新记录，同时显示新增数量。
- 上传或恢复操作成功后，当前页面立即刷新并将返回的新事件标记为已见，避免随后轮询重复提示自己的操作。
- 其他成员的上传和恢复都触发提示；筛选条件和搜索词保持不变，新数据按现有筛选规则显示。
- 会话失效时停止轮询并返回登录页；普通网络错误不清空现有内容，等待下一次检查重试。

## 提示方式

- 继续复用工作台顶部现有提示区域，不增加浏览器系统通知、声音、邮件或短信。
- 提示仅在网页处于打开状态时生效；浏览器关闭或系统挂起期间不保证即时通知，重新打开或恢复前台后会立即检查。
- 提示文案简洁，例如“陈鑫上传了代码 v028，页面已刷新”。
- 页面不显示内部轮询状态或技术错误细节。

## 组件与边界

- 上传路由只负责请求校验和把文件交给 GitHub 数据层，不包含分块细节。
- GitHub 数据层负责选择单文件或分块模式、生成清单、原子提交和透明下载。
- 工作台负责定时检查、已见事件状态、提示和摘要替换，不直接访问 GitHub。
- 不新增数据库、对象存储、Git LFS、第三方通知服务或后台推送服务。

## 错误处理

- 任一分块上传失败时不更新目标分支，版本索引不会出现不完整记录。
- 分块清单缺失、格式错误、分块丢失或总大小不一致时返回通用中文下载错误，不暴露 GitHub 响应或令牌。
- 30 秒检查失败时保留当前页面内容，不反复弹出错误；下一次轮询、回到前台或网络恢复时重试。
- 超过 50 MiB 的文件在浏览器选择后立即提示，服务端仍进行独立校验，不能通过绕过前端上传超限文件。

## 测试与验收

- 50 MiB 文件通过前后端大小校验，超过 1 字节即被拒绝。
- 10 MiB 及以下使用普通 blob；超过 10 MiB 使用 5 MiB 分块和清单。
- 分块清单顺序、原文件名、总大小和完整 SHA-256 正确。
- 普通文件与分块文件都能下载为原始字节和原始文件名。
- 分块缺失、非法路径或大小不一致时下载失败。
- 普通版本和分块版本都能恢复，已有历史记录保持兼容。
- 首次加载不提示；检测到新事件后显示提示并替换摘要；自己的上传或恢复不重复提示。
- 轮询每 30 秒运行，页面回到前台和网络恢复会立即检查，卸载页面时清理计时器和监听器。
- 登录、权限、在线、下载日志、上传、恢复等现有测试继续通过。
- 代码检查、生产构建、敏感信息扫描通过后发布到现有公开网址。

## 已知限制

- 50 MB 大文件仍需要进入网站服务器，实际成功率受用户网络、Cloudflare 请求体限制、Worker 128 MB 内存和 GitHub API 可用性影响；分块主要降低出站编码的峰值内存，不等于消除所有平台限制。
- 分块文件在 GitHub 仓库中显示为清单和分块，建议团队通过版本站下载，不直接从 GitHub 内容页下载清单。
- 30 秒轮询是近实时而非即时推送，正常提示延迟最多约 30 秒。
