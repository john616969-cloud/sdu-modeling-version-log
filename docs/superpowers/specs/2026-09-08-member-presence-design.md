# 成员在线记录设计

## 目标

在现有数模版本站中记录成员每段在线使用的上线时间和最后活跃时间。只有张怡慧的管理员页面可以读取和显示成员在线记录；普通成员只负责上报自己的活跃状态，不能读取任何成员的在线记录。

## 在线判定

- 已登录页面成功加载后立即上报一次活跃状态，此后每 5 分钟上报一次。
- 页面从后台重新回到前台或网络恢复时立即补充上报一次。
- 服务端使用自己的北京时间生成时间戳，不接受客户端提交的时间。
- 最近一次活跃时间距当前服务端时间不超过 10 分钟时显示“在线”，超过 10 分钟显示“离线”。
- 浏览器关闭、断网或电脑休眠不依赖不可靠的“离开页面”事件；停止上报后会自然转为离线。

## 在线时段与多电脑

- 每个七天签名会话包含服务端生成的随机会话 ID，不包含设备名称或设备指纹。
- 首次收到某会话的活跃上报时创建一段在线记录，`online_at` 和 `last_active_at` 均为当前时间。
- 同一会话后续在 10 分钟内上报时只更新该段记录的 `last_active_at`。
- 同一会话在超过 10 分钟后再次上报时创建新的在线时段，新的 `online_at` 为恢复活跃的时间。
- 同一成员在多台电脑上的不同会话分别记录。管理员页面按成员汇总当前状态：任一会话在 10 分钟内活跃即为在线；上线时间显示当前活跃时段中最早的时间，最后活跃时间显示最新时间。
- 历史表格保留每段记录，便于查看过去何时上线和最后活跃。

## 数据结构与存储

- 在线记录继续存入现有私有 GitHub 数据仓库，不新增数据库或第三方服务。
- `presence/index.json` 保存最近 500 段在线记录，按最后活跃时间倒序排列。
- 每段记录包含：记录 ID、成员姓名、会话 ID、上线时间、最后活跃时间。
- 服务端写入采用现有 Git Data API 原子提交和最多三次并发冲突重试。
- 为避免页面短时间重复触发导致额外提交，如果同一在线时段距上次持久化不足 4 分钟，服务端直接返回成功而不写 Git 提交。
- 在线数据不进入公开源码仓库，不记录密码、Cookie、IP 地址、位置、设备详情或浏览轨迹。

## 接口与权限

- 新增在线接口的 `POST` 操作：要求有效成员会话，从签名会话读取成员和会话 ID，并写入或更新在线时段。客户端不能指定成员姓名。
- 在线接口的 `GET` 操作：要求管理员会话，返回最近 500 段在线记录和基于当前服务端时间计算的状态。
- 普通成员调用 `GET` 返回 `403`，未登录调用任一操作返回 `401`。
- 所有响应使用 `Cache-Control: private, no-store`。
- 页面定时上报失败不会退出登录或阻断上传、恢复和下载；下一次定时上报会重试。

## 页面行为

- 张怡慧的页面在现有登录日志后增加“成员在线记录”。
- 顶部汇总区按三名成员显示“在线/离线”、本段上线时间和最后活跃时间。
- 下方历史表格显示成员、上线时间、最后活跃时间和状态，最新活跃记录在前。
- 普通成员页面不渲染该区域，也不发起读取请求，但仍按计划上报自己的活跃状态。
- 页面卸载时停止计时器，不尝试伪造精确下线时间。

## 会话迁移

- 会话载荷新增随机会话 ID。发布后缺少会话 ID 的旧 Cookie 视为无效，所有设备需重新登录一次。
- 新会话仍保持七天有效期；七天到期后重新登录会获得新的会话 ID。

## 错误处理

- GitHub 暂时不可用或发生最终并发冲突时，上报接口返回临时错误，页面静默等待下一次上报。
- 管理员读取失败时只在在线记录区域显示简洁重试提示，不展示仓库响应、令牌或堆栈。
- 存储中出现格式不完整的历史记录时忽略无效项目，不影响其他记录展示。

## 测试与验收

- 新会话包含不可预测的会话 ID，篡改会话内容会使签名校验失败。
- 首次上报创建在线时段；10 分钟内上报更新同一时段；超过 10 分钟后创建新时段。
- 4 分钟内的重复上报不产生新的 Git 提交。
- 多个会话按成员正确汇总，在线与离线边界基于服务端时间计算。
- 普通成员可以上报自己的状态但读取返回 `403`；管理员可以读取；匿名请求返回 `401`。
- 普通成员不能通过请求正文冒充其他成员。
- 在线记录最多保留 500 段，所有接口禁止缓存。
- 现有登录、下载、上传、恢复和七天会话测试继续通过。
- 代码检查、生产构建和敏感信息扫描通过后发布，并进行不伪造成员活动的线上匿名权限检查。

## 已知限制

- 在线状态是基于心跳的近似值，不是操作系统级的实时在线检测，最多可能有约 10 分钟延迟。
- GitHub 作为在线状态存储会产生较多私有仓库提交；三人竞赛规模下可接受，但不适合大团队或长期高频使用。
- 拥有私有数据仓库或托管环境管理权限的人仍可直接访问底层记录；“只有张怡慧可见”指网站应用权限。
